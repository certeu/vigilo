## Objective

Scan all dependency manifests in the repository at {{REPO_PATH}} to identify third-party packages with known security vulnerabilities (CVEs, GHSAs). Use **WebSearch** and **WebFetch** to look up each package and version against public advisory databases.

Read the code analysis at `deliverables/code_analysis_deliverable.md` for technology stack context (languages, frameworks, package managers in use).

## Methodology

### Step 1: Discover Dependency Manifests

Search the repository for all dependency manifest files. Common manifests include:

| Ecosystem | Manifests |
|-----------|-----------|
| Python    | `requirements.txt`, `Pipfile.lock`, `poetry.lock`, `setup.py`, `pyproject.toml` |
| Node.js   | `package.json`, `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml` |
| Java      | `pom.xml`, `build.gradle`, `build.gradle.kts` |
| Go        | `go.mod`, `go.sum` |
| Ruby      | `Gemfile.lock` |
| PHP       | `composer.json`, `composer.lock` |
| Rust      | `Cargo.toml`, `Cargo.lock` |
| .NET      | `*.csproj`, `packages.config`, `Directory.Packages.props` |

Skip directories: `node_modules/`, `.venv/`, `vendor/`, `dist/`, `build/`, `.git/`.

Use `find` and `grep` to locate manifests. Read each one to extract (package_name, version) pairs.

### Step 2: Research Vulnerabilities

For each package+version found, **use WebSearch to look up known CVEs and security advisories**. Search queries should target:
- `"<package_name>" "<version>" CVE site:nvd.nist.gov OR site:github.com/advisories OR site:osv.dev`
- `"<package_name>" security advisory vulnerability`

For each vulnerability found, determine:
- **Advisory ID**: CVE or GHSA identifier
- **Severity**: Based on CVSS score (Critical >= 9.0, High >= 7.0, Medium >= 4.0, Low < 4.0)
- **Affected version range**: Confirm the installed version is actually affected
- **Fixed version**: The minimum version that patches the issue (if available)
- **Description**: Brief summary of the vulnerability and its impact

**Only report vulnerabilities that affect the specific installed version.** If a CVE was fixed in a version older than what is installed, do NOT include it.

### Step 3: Prioritize by Risk

Group and prioritize findings:
1. **Critical/High severity** with a known fixed version — immediate upgrade recommended
2. **Critical/High severity** with no fix available — risk acceptance or replacement needed
3. **Medium/Low severity** — include for completeness but lower priority

Consider transitive vs direct dependencies when noting remediation paths.

## Output Format

Save your findings as a JSON file with this exact structure:

```json
{
  "manifests_scanned": 3,
  "packages_scanned": 127,
  "vulnerabilities": [
    {
      "ID": "SCA-VULN-001",
      "package": "lodash",
      "version": "4.17.15",
      "ecosystem": "npm",
      "manifest": "package-lock.json",
      "vulnerability_type": "Supply_Chain",
      "cve_ids": ["CVE-2021-23337"],
      "severity": "high",
      "title": "Prototype Pollution in lodash",
      "description": "lodash before 4.17.21 is vulnerable to Command Injection via the template function.",
      "fixed_version": "4.17.21",
      "references": ["https://nvd.nist.gov/vuln/detail/CVE-2021-23337"],
      "code_fixable": false,
      "status": "unconfirmed"
    }
  ]
}
```

Field rules:
- **ID**: Sequential `SCA-VULN-001`, `SCA-VULN-002`, etc.
- **severity**: One of `critical`, `high`, `medium`, `low`
- **code_fixable**: Always `false` (SCA findings require dependency upgrades, not code patches)
- **status**: Always `unconfirmed` (these are known CVEs, not confirmed exploits against this app)
- **fixed_version**: The minimum safe version, or `null` if no fix is available
- **cve_ids**: Array of all associated CVE/GHSA identifiers
- **manifest**: The filename where this dependency was found

## Deliverables

Save your findings using:
```
save-deliverable --type SCA_FINDINGS --content '{"manifests_scanned": N, "packages_scanned": N, "vulnerabilities": [...]}'
```

For large results (many vulnerabilities), write to a temp file first:
```
save-deliverable --type SCA_FINDINGS --file-path /tmp/sca_findings.json
```

If no dependency manifests are found, save an empty result:
```
save-deliverable --type SCA_FINDINGS --content '{"manifests_scanned": 0, "packages_scanned": 0, "vulnerabilities": []}'
```

When complete, output: SCA ANALYSIS COMPLETE
