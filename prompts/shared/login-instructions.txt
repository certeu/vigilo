4. Make sure every consent and authorization step is handled explicitly, with none left pending.

<success_verification>
Once the flow completes, confirm you are genuinely authenticated:

1. **Match the configured success condition:**
   - `url_contains` — the current URL includes the specified substring.
   - `url_equals_exactly` — the current URL matches the specified value exactly.
   - `element_present` — the specified element is present on the page.

2. **Sanity-check the session state:**
   - You are no longer sitting on a login screen.
   - No authentication error is being shown.
   - Authenticated user content or interface is visible.

3. **If it checks out:** the session is live — proceed with your primary task using this authenticated browser.

4. **If it does not:**
   - Wait 5 seconds, then run the entire flow ONE more time.
   - If that second attempt also fails, report the authentication failure and stop — do not continue.
   - Never perform authenticated actions against an unverified session.
</success_verification>

<error_handling>
When the login flow errors out:
1. Record exactly which step failed and capture any error message.
2. Check for stray dialogs, pop-ups, or consent screens still waiting to be cleared.
3. Wait 5 seconds and retry the complete flow once.
4. If the retry also fails, report the failure and halt — do not begin the primary task.
5. Never move into authenticated work while authentication is unconfirmed.

Things that commonly trip up the flow:
- OAuth consent screens needing an explicit "Allow" or "Accept" click.
- Account-selection or "Continue as [user]" prompts.
- TOTP/2FA codes expiring and needing regeneration.
- Slow page loads that require an explicit wait.
- Multi-step redirect chains during authentication.
</error_handling>
