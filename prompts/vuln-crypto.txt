## Objective

Analyze the target application's source code at {{REPO_PATH}} for cryptographic weaknesses. This is primarily a source code analysis — you do NOT need a browser session for this analysis.

Read the code analysis at `deliverables/code_analysis_deliverable.md` and reconnaissance at `deliverables/recon_deliverable.md` before starting.

Read `deliverables/shared_context.json` for accumulated knowledge from prior agents.

## Methodology

### 1. Key Management
- Hardcoded cryptographic keys, secrets, or passwords in source code
- Weak key generation (insufficient entropy, predictable seeds)
- Missing key rotation mechanisms
- Keys stored in version control or config files

### 2. Encryption Analysis
- Use of deprecated algorithms (DES, 3DES, RC4, MD5 for security, SHA1 for security)
- ECB mode usage (patterns preserved)
- Missing or static initialization vectors (IVs)
- Insufficient key lengths (RSA < 2048, AES < 128)

### 3. Hashing & Password Storage
- Plaintext password storage
- Use of fast hashes for passwords (MD5, SHA1, SHA256 without stretching)
- Missing or weak salt in password hashing
- Insufficient work factor for bcrypt/scrypt/argon2

### 4. Token & Session Security
- Predictable token generation
- JWT vulnerabilities (none algorithm, weak secret, missing expiry)
- Session ID entropy analysis
- CSRF token weakness

### 5. TLS/Transport Security
- Insecure TLS configuration in code
- Certificate validation disabled
- Mixed content issues
- HSTS missing or misconfigured

### 6. Random Number Generation
- Use of Math.random() or similar non-CSPRNG for security purposes
- Predictable seeds for random number generators
- Insufficient entropy sources

## Deliverables

Save your analysis using:
```
save-deliverable --type CRYPTO_ANALYSIS --file-path /tmp/crypto_analysis.md
```

Save your exploitation queue (all confirmed findings as structured JSON):
```
save-deliverable --type CRYPTO_QUEUE --content '{"vulnerabilities": [...]}'
```

Each finding in the queue MUST follow the `exploitation_queue_format` above. Include ALL findings — both code-fixable issues (weak algorithms, missing validation) and infrastructure issues (missing TLS, env var configuration). Set `externally_exploitable` based on whether the weakness is reachable from the internet.

Update `deliverables/shared_context.json` with any new discoveries (especially credential-related findings).

When complete, output: CRYPTO ANALYSIS COMPLETE
